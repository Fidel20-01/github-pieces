## ¿Qué son estas piezas?

GitHub permite organizar un proyecto de requisitos con herramientas simples y visuales. En esta práctica se usan tres piezas clave para documentar, clasificar y estandarizar la información del proyecto.

<table>
  <tr>
    <td align="center" width="33%">
      <h3>📘 Issue</h3>
      <p><strong>Un requisito.</strong> Tiene número, autor, estado y conversación.</p>
      <p>Sirve para registrar una necesidad, tarea o problema del proyecto.</p>
    </td>
    <td align="center" width="33%">
      <h3>⭐ Etiqueta</h3>
      <p><strong>El tipo (F, NF, D), la prioridad y la fuente.</strong></p>
      <p>Permite clasificar cada requisito y facilitar su análisis y priorización.</p>
    </td>
    <td align="center" width="33%">
      <h3>⚙️ Plantilla</h3>
      <p><strong>Un formulario que obliga a todos a escribir igual.</strong></p>
      <p>Estándariza la forma de redactar los requisitos y reduce información inconsistente.</p>
    </td>
  </tr>
</table>

---

## Aplicación en el proyecto

En el módulo de gestión de pedidos y producción del proyecto de la Panadería “Burritos”, estas tres piezas ayudan a sistematizar los requisitos funcionales y no funcionales de la siguiente manera:

- <strong>Issue</strong>: cada requisito se registra como un elemento independiente con su número y estado.
- <strong>Etiqueta</strong>: se marca si es funcional, no funcional o defecto; además se indica prioridad y origen.
- <strong>Plantilla</strong>: cada issue se escribe con la misma estructura para evitar diferencias en la redacción.

### Ejemplo de requisito

- <strong>RF-01</strong> · Registrar pedido
- Descripción: El sistema debe permitir registrar un pedido con nombre del cliente, cantidad de piezas y fecha de entrega al momento de recibirlo.
- Etiquetas: `rf`, `debe`
- Fuente: A1, A2 (P18-19)

---

## ¿Por qué es útil?

Estas piezas permiten:

- mantener una trazabilidad clara de cada requisito,
- clasificar tareas por tipo, prioridad y origen,
- estandarizar la redacción de información,
- mejorar la colaboración del equipo,
- y facilitar la organización del proyecto en GitHub.
