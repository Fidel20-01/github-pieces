# Las piezas de GitHub

GitHub ofrece varias herramientas que ayudan a organizar y controlar requisitos de un proyecto. En esta práctica se destacan tres piezas clave:

## 1. Issue
Un requisito. Tiene número, autor, estado y conversación.

Los Issues se usan para registrar tareas, requerimientos o problemas. Cada uno tiene:
- número único,
- autor que lo crea,
- estado (abierto, cerrado, en revisión, etc.),
- y una conversación con comentarios.

## 2. Etiqueta
El tipo (F, NF, D), la prioridad y la fuente.

Las etiquetas permiten clasificar los requisitos para facilitar su organización y seguimiento. Por ejemplo:
- Tipo: F (funcional), NF (no funcional), D (defecto)
- Prioridad: alta, media, baja
- Fuente: cliente, usuario, análisis, error, investigación

## 3. Plantilla
Un formulario que obliga a todos a escribir igual.

Las plantillas estandarizan la forma en que se redactan los Issues. Esto ayuda a que todos los requisitos tengan la misma estructura, evitando información incompleta o inconsistente.

## Ejemplo de uso
Un equipo puede crear un Issue para un requisito funcional, asignarle etiquetas según tipo y prioridad, y usar una plantilla para que todos escriban la información de la misma manera.

Esto hace más clara la gestión del proyecto, mejora la trazabilidad y facilita la revisión de requisitos.
